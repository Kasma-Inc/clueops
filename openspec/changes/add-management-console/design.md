## Context

现有 REST 实例固定租户、会话和调用身份。调查与目标权限由 Core 校验，原始 YAML 和插件配置包含私密连接信息，不能作为管理接口直接返回。

## Decisions

- REST 配置显式设置 `admin: true` 开启 `/admin/`，默认关闭；复用该实例的 Bearer Token。页面仅在内存保存 Token，刷新后重新连接。
- Core 提供公共的可选管理读取合同，由 Host 绑定渠道身份。列表在授权过滤后分页；详情及证据使用相同的当前调用者的目标授权校验，来源只作为元数据，历史读取不要求当前执行范围版本相同。
- 不新增持久状态或数据库，读取现有 acceptance、turn、evidence。调查状态取最后一个诊断轮次，状态查询等控制操作不覆盖它。
- 目标页返回运行时安全快照：引擎、工具资源范围、知识条目数量、技能名称；不返回原始配置、凭证、技能目录或知识文件路径。
- 详情按轮次分页，证据单独分页并限制预览长度，避免大结果阻塞页面。报告、输入和证据在输出边界再次脱敏。
- 用户选定浅色、紧凑的运维控制台：左侧固定导航，记录表格为首页，详情按问题、报告、证据组织。移动端导航横排、表格横向滚动。覆盖连接、加载、空白、错误、权限失效和追问提交状态。
- 原生 HTML/CSS/JS 与服务同源托管，使用严格 CSP 和文本渲染；构建时将资源复制到 dist，无新增依赖。当前入口身份负责认证，调查读取和显式编号关联遵循渠道无关目标授权，详见 `decouple-investigations-from-channels`。

- 目标、状态和搜索词保留手动提交：点击“筛选”或按回车才应用。草稿条件与已应用条件分开，页面明确提示待提交变化；刷新和分页不会隐式应用草稿。
- 列表只更新结果区，保持表单与焦点；请求绑定视图和登录会话，后续请求取消并取代旧请求。导航切换后恢复页首和主内容焦点。
- 详情稳定复用每个轮次及证据节点，更新状态和报告不会清除展开状态；暂时请求失败后继续轮询，分页合并不回退状态，并补读刷新期间产生的中间轮次。
- 新证据可能按时间与编号排序到已读区间之前；总数增长时从头扫描并按编号去重，保留已有证据节点；处理证据响应与详情计数交错的情况。

## Verification

通过类型检查、管理 API 集成测试验证权限过滤、分页、脱敏、追问与重启读取；执行现有回归测试。浏览器验证桌面和移动端以及主要交互状态。
