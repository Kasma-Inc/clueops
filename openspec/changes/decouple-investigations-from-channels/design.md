## Context

目标权限由认证入口的 routes 映射。原 Principal 同时用于当前调用者授权和每轮来源溯源；错误在于把创建来源恒等条件加入了调查所有权、存储及恢复。平台消息 ID 不全局唯一，回复与回执仍需要渠道地址命名空间。

## Decisions

- investigationId 是调查关联键，同一调查的所有轮次保持目标快照一致及 sequence 连续；每轮保留自己的认证主体和输入地址，二者必须一致，不要求与首轮地址相同。
- 新请求由当前认证主体获得目标授权，显式 investigationId 可以跨渠道、群和会话关联。replyToMessageId 仍只解析当前平台地址中的消息，不能跨插件猜测关联。
- Core 的 InvestigationReader / InvestigationReadAccess 是统一调查读取能力，列表、详情和证据按当前目标权限校验。来源是元数据，历史目标版本不影响读取；canContinue 表明当前目标版本是否仍能执行该调查。
- 诊断追问与续接使用当前主体的目标授权，并保持原目标版本；状态、取消和投递重试只要求当前目标授权，保持调查原快照，不调用 Agent。
- 已持久受理的诊断任务使用受理时的授权决定；执行前仍校验当前目标资源版本。停用输入插件不撤销调查，已受理控制可恢复执行，调查的报告和证据仍可读取。
- 投递只使用本轮原地址；原插件不可用时等待恢复，不改投到别处。发送时校验原收件方当前目标授权，不能借用重试者权限。投递历史报告不混用工具执行范围的版本校验。即使适配器缺失也持久化通用文本投递计划，尤其不能丢弃已处理控制的结果，或通过再次执行控制来补回复。
- REST 的 /api 调查数据接口对认证且获相应目标权限的调用者开放，admin 只控制页面资源。GET /messages 仍表示该 REST 实例的投递邮箱；跨入口输入、报告和证据从统一调查接口读取，避免将传输收据作为调查事实来源。
- messageKey 的平台地址命名空间、每轮出站地址校验和回执地址校验保留，防止消息 ID 碰撞、重复执行和错误投递。

## Compatibility

旧 v1 记录可直接读取，无凭证或历史数据迁移。写入跨渠道轮次后，旧二进制的地址恒等约束会拒绝恢复该目录；回滚需要使用跨渠道写入前的状态备份，不能声称新数据可被旧版本直接读取。

## Verification

验证跨插件/租户/会话追问、控制、返回原入口续接及重启；未获目标权限拒绝；同名平台消息不冲突，跨源回复 ID 不猜关联；原插件停用后已受理调查继续执行；旧目标版本历史可读但诊断不可执行；投递重试保留原地址并受原收件方授权约束。运行公共接口、存储、渠道、全量及浏览器回归。
